\subsection{Training Procedure}
\label{sec:phase3_training}

\paragraph{Framework and CPU rationale.}
The reference network is implemented in PyTorch (CPU build): a multilayer perceptron
with hidden widths $(256,256,128)$, dropout $0.1$, and two heads (regression and a
10-bin distance classifier). The training loop supports mini-batching, AdamW, gradient
clipping, early stopping, and checkpointing of the target statistics. A network of this
size does not benefit materially from a GPU, and a CPU-only setup keeps the experiment
reproducible on any team laptop. The complete PyTorch training and evaluation path is
unit-tested.

Because a full PyTorch training run on the 4.4-million-cell training split exceeds the
course's CPU budget, the \emph{committed benchmark} uses a scikit-learn MLP with the
same 29-feature interface and the same target normalisation. The shipped PyTorch
checkpoint is a one-epoch smoke test (20{,}000 cells per epoch) used to validate the
pipeline; it is audited in Phase~5 and is not the source of any reported search number.

\paragraph{Data split.}
Mazes, not cells, are split $70/15/15$ into train, validation, and test sets
(1{,}313, 281, and 282 mazes; 4{,}407{,}160, 896{,}328, and 911{,}949 labelled cells).
Splitting by maze prevents cells of one maze from appearing on both sides of the split.
The assignment is deterministic (seed $42$) and stored in
\texttt{results/manifests/split\_manifest.json}; the same manifest selects the held-out
test mazes for every search experiment.

\paragraph{Target and normalisation.}
The regression target is $y=h^\ast(n)/N$, the optimal remaining cost normalised by the
grid side $N$. Its empirical range is $[0,3.18]$, because an optimal path that winds
around walls can be longer than $N$ cells. The PyTorch pipeline standardises the target
using training-split statistics stored in the checkpoint
($\mu=0.7381$, $\sigma=0.3683$ in the smoke run); the scikit-learn fallback trains
directly on $y$ and multiplies predictions by $N$ at inference. Cells with the $-1$
sentinel (walls and unreachable cells) are excluded from training and evaluation.

\paragraph{Fallback training configuration.}
The evaluated regressor is trained on 100{,}000 cells sampled uniformly from the training
split (seed $42$), using two hidden layers of 64 units, ReLU activations, Adam, early
stopping with a $5$-epoch patience, and at most 50 epochs. It converges after 17 epochs
with a final training loss of $0.00763$ and a best internal validation score of $0.8714$.
A companion 10-bin classifier with the same architecture is trained on quantile bins of
$y$ and converges after 21 epochs. Table~\ref{tab:fallback_config} records the settings;
Table~\ref{tab:regression_results} in Phase~4 reports the resulting test metrics.

\paragraph{Reproducibility.}
Training is a single command (\texttt{python scripts/train\_fallback\_models.py}) and
depends only on the processed training matrix, which is itself regenerated
deterministically from the raw mazes. The scikit-learn artefacts are committed with
SHA-256 checksums and can be rebuilt given the same seed and environment; the evaluation
CSV and all Phase~5 statistics are tracked.
